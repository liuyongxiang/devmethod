# 项目技术参考 ROUTE.md 规范

本规范定义 devmethod 插件的项目适配层：**每个项目**在 `.agents/agent-docs/ROUTE.md`
维护一份技术参考（可选；不存在时各技能以项目入口文档与实际代码为准）。
插件五个技能（design / dev / review / testing / coding-flow）的通用流程都从这里读取项目差异。

ROUTE.md 是导航与红线清单，不是全仓审计，也不替代 spec 与契约真相源；
其中引用的路径、符号与命令必须真实存在。项目代码演进后同步修订，读到与实际不一致时当场核实更新。

## 消费方式

- **coding-flow / dev / design / review / testing**：开工前读「仓库定位」「模块与依据导航」确认影响面；
- **dev / review**：逐条核对「项目红线」与「验证和文档口径」列出的命令；
- **testing**：从「验证和文档口径」取测试环境与执行入口。

## 建立时机

新项目接入插件后，第一次开发任务前用本规范建立 ROUTE.md（半天量级，可随任务增量补齐）；
已有项目可先写最小版：仓库定位 + 模块表只列当前要动的模块，红线先照抄入口文档的硬性规则。

## 可复制骨架

以下骨架整体复制到 `.agents/agent-docs/ROUTE.md`，替换 `〈占位内容〉`，删除不适用的行；
条目宁缺毋滥——每行都要经得起「grep 得到、跑得起」的核实。

````markdown
# 〈项目名〉技术参考（ROUTE）

> 供 devmethod 插件技能消费的项目适配层；命令与路径必须真实存在，代码演进后同步修订。
> 最近核对日期：〈YYYY-MM-DD〉

## 1. 仓库定位

〈2-5 句：项目是什么、技术栈与版本约束、对外形态（库 / 应用 / 插件）、
基于什么基座或框架（若为增量项目，说明如何区分自研层与继承层，如基线 tag / 目录边界）〉

## 2. 模块与依据导航

模块标识供受管文档 frontmatter `modules` 与索引分组使用；一行一个模块。

| 模块标识 | 技术职责与需审视的边界 | 真实入口 / 规则与契约依据 |
|---|---|---|
| 〈module-slug〉 | 〈职责一句话 + 检视要点（同步纪律、执行形态、方言陷阱等）〉 | 〈存在的入口文件路径 / 入口文档章节 / spec 目录〉 |

## 3. 公共契约注意点

本项目检视与开发必须知道的全局契约事实（每条经核实）：

- 〈契约真相源位置：schema / DDL / 协议定义在哪，是否有多份必须同步配套的（双份方言、双目录）〉
- 〈外部系统陷阱：数据库 / 平台的特殊行为与绕法〉
- 〈默认值纪律：默认值按什么形态写，环境差异如何注入〉
- 〈安全边界：凭据处理、危险调用、脱敏要求〉
- 〈领域词表：受管文档 `domain` 字段建议使用的标识（可选）〉

## 4. 项目红线

入口文档硬性规则中「违反即返工」的子集，逐条列出（来源注明入口文档章节）：

- 〈红线一：如某类操作必须同步阻塞执行〉
- 〈红线二：如改某目录后必须同步到另一目录〉
- 〈红线三：如凭据进入某类工件前必须脱敏〉

## 5. 验证和文档口径

| 用途 | 命令 / 入口 |
|---|---|
| 单元测试 | 〈实际命令〉 |
| lint / 类型检查（增量） | 〈实际命令；注明禁止项，如全量检查、格式化工具〉 |
| 构建（改后必须跑的） | 〈实际命令〉 |
| 本地运行 | 〈实际命令 + 地址 / 端口〉 |
| 工具链门禁（若有） | 〈发布 / 归档 / CI 相关命令〉 |

- 提交约定：〈提交信息风格、提交位置、push 目标、MR 时机——引用入口文档章节〉
- 文档同步：〈spec / 受管文档之外，本项目要求同步的文档与规则文件〉
````

## 维护纪律

- 路径、符号、命令必须能定位与执行；**禁止想当然写不存在的入口**——引用前先核实。
- 条目随代码演进更新；模块新增时补行，入口移动后改链接，过期内容当场删除并注明原因。
- 红线与命令的权威来源始终是项目入口文档；ROUTE.md 是面向插件技能的浓缩视图，两处冲突时以入口文档为准并修正本文件。
- 不在 ROUTE.md 里复制 spec 内容或进度状态——它只做导航与红线，每个事实保留一个维护位置。
